# Second Brain — Agent Contract (Karpathy LLM Wiki pattern)

This vault is a **personal second brain maintained by an LLM**. You (the agent) are the *librarian*:
the human curates **what** goes in; **you** build and maintain the knowledge base.

Implementation idea: Andrej Karpathy's "LLM Wiki" — raw immutable sources in `raw/`, an LLM-maintained
`wiki/` of interlinked markdown. No RAG, no embeddings, no proprietary schema: plain markdown that fits in
a long-context window and is auditable by a human in Obsidian.

## Scope of this brain
General-purpose: **work** topics, **behavior / performance / productivity** studies, **articles**, and
personal **notes & ideas**. Wiki content is written in **English** (technical terms stay in English even
when a source is in Portuguese).

## Folder map
```
raw/                 # immutable source material — READ ONLY, never edit or move these
  inbox.md           # quick fleeting capture (append on top); drained by /process-inbox
  assets/            # images/attachments belonging to sources
wiki/                # everything here is written and maintained BY YOU
  sources/           # one summary page per ingested source (cites original path/URL)
  entities/          # people, companies, products, tools
  concepts/          # ideas, frameworks, techniques, definitions
  synthesis/         # cross-cutting analyses, comparisons, themes
  index.md           # master catalog / map of content — keep current
  log.md             # APPEND-ONLY operation log — never rewrite past entries
output/              # answers/reports generated by /query
review/              # LEARNING LAYER — spaced-repetition state
  queue.md           #   the card deck (Q/A + Leitner box + due session) — you maintain this
areas/               # OPERATIONAL LAYER — state, plans, artifacts (Portuguese); see section below
journal/             # chronology — one note per day, one per week (Portuguese)
templates/           # Obsidian templates used by the skills (diario, semana, trilha, post, decisao, tese, projeto)
scripts/             # deterministic helpers — os_status.py prints the system state as JSON
docs/                # specs and design docs for this vault (personal-os-spec.md)
```

## Hard rules
1. **Never edit, move, or delete** anything in `raw/`. They are the source of truth.
2. **Every wiki page cites its source(s)** in a `## Source(s)` section at the bottom (relative path or URL).
3. Connect pages with `[[wikilink]]`. If a linked page does not exist yet, create a stub for it.
4. After any change: **update `wiki/index.md`** and **append one entry to `wiki/log.md`** (date, operation, source, pages touched). Never rewrite the log.
5. On conflict with existing content, **flag it** under a `## Contradictions` section on the page — do not silently overwrite the old claim.
6. Plain markdown only. Optional lightweight frontmatter (`type:`, `source:`) is allowed for future Dataview use, but never required.
7. **Portability:** use vault-relative paths with `/` separators. Do not assume macOS or Windows. Do not invent shell scripts inside wiki pages.

## Slug & page conventions
- Filenames: lowercase, words separated by `-` (e.g. `wiki/concepts/big-o-notation.md`).
- Page shape: `# Title` → short summary → body sections → `## Related` (wikilinks) → `## Source(s)`.

## Learning layer (study pipeline)
This brain is also a **study machine**, built on learning science: active recall, spaced repetition,
interleaving, and elaboration (Feynman). Mechanics:

- **Recall cards live on the page.** Every `concepts/` and `synthesis/` page should end with a `## Recall`
  section: 2–5 question→answer pairs that test understanding (not trivia).
- **Scheduling lives in `review/queue.md`** as one block per card. Format:
  ```
  ## Card: <slug>
  - page: [[page-name]]
  - box: <1-5>
  - due: <session number>
  - Q: <question>
  - A: <answer>
  ```
- **Leitner boxes** = intervals in *sessions* (not calendar days — scripts have no reliable date):
  box 1→due in 1, 2→2, 3→4, 4→8, 5→16 sessions. Correct answer = box +1 (max 5); wrong = back to box 1.
- A **`session:` counter** is kept at the top of `review/queue.md`. `/study` increments it once per run,
  reviews every card with `due <= session`, grades the user's answer against `A`, and rewrites `box`/`due`.
- When `/ingest` or `/process-inbox` create/expand a page, they also add its `## Recall` cards to `review/queue.md`
  at `box: 1, due: <current session>`.

## Operational layer (areas/ + journal/)
The wiki stores KNOWLEDGE. The operational layer stores STATE: what the user is studying and why, what they
will publish, work decisions, personal goals, and the chronology of all of it.

- `areas/estudos/`   gap-map.md (skill levels per AI domain) and trilhas/<slug>.md (one study track each).
- `areas/teses/`     one file per public position the user holds: argument, evidence, what would change their
                     mind, revision history. Posts and articles are born here, not only from study.
- `areas/projetos/`  one file per public project (code, benchmark, tool, paper): goal, status, what shipped,
                     who uses it. The strongest form of public output.
- `areas/publico/`   estrategia.md, voz.md, ideias.md (post backlog) and posts/<date>-<slug>.md.
- `areas/rede/`      mapa.md: people with a public presence the user wants to debate, learn from or work with.
                     Name + public handle + why + public interactions only. Nothing private about anyone.
- `areas/trabalho/`  frentes/<front>.md (decisions and learnings per work front) and aprendizados.md.
- `areas/pessoal/`   metas.md and habitos.md.
- `journal/`         one note per day (YYYY-MM-DD.md) and one per week (semanas/YYYY-Www.md).

Routing rule: a reusable idea, concept or fact goes to the wiki (via raw/inbox.md or /ingest). A plan, a
status, a decision or an artifact goes to areas/. What happened on a given day goes to journal/. Never
duplicate; link with [[wikilinks]].

North-star metric: public output that other people use or cite, weighted project > long article > post.
The weekly review opens with it. Cards reviewed and wiki pages are means, never the score.

Language: wiki in English (unchanged). areas/ and journal/ in Portuguese, technical terms in English.

Dates: you DO have the date. Run `date +%F` (Bash) at the start of any operation that writes a date and
use it in log.md, journal/, posts and track sessions. Never write `date: unknown` again.

Privacy (LGPD): areas/trabalho/ holds decisions and reasoning, never personal data of creators, clients
or employees (names of natural persons, emails, phones, IDs, individually identifiable metrics). Refer
to people by role. If the user pastes such data, keep it out of the file and say so.

Deterministic state comes from `python scripts/os_status.py` (due cards, active tracks, posts by status,
today's date). Skills call it instead of recomputing by reading files.

## Commands available
- `/ingest <path-or-URL>` — ingest a source; also writes `## Recall` cards and enqueues them.
- `/process-inbox` — triage `raw/inbox.md` items into the wiki (same recall treatment).
- `/query <question>` — answer from the wiki, save to `output/`.
- `/lint` — health check (broken links, orphans, missing citations, contradictions, index gaps).
- `/study` — run a spaced-repetition session (interleaved across topics).
- `/gaps` — learning health check: shallow/stub pages, pages without `## Recall`, frequently-missed cards → study plan.
- `/explain <concept>` — Feynman mode: user explains, the agent grades and patches gaps, may add recall cards.

Skills (operational layer, in `.claude/skills/`; interactive ones ask one question at a time):
- `/diagnostico` — diagnostic interview over nine AI domains → writes `areas/estudos/gap-map.md`. First run and quarterly.
- `/trilha nova|continuar|listar|fechar` — study tracks in `areas/estudos/trilhas/`: motivation, scope, sources, sessions, output artifact.
- `/dia` — opens the day: reads state, writes `journal/<today>.md` with a plan of at most three items.
- `/semana` — weekly review across all areas → `journal/semanas/<week>.md`; opens with public output, sets next week's focus.
- `/ideias [n]` — post ideas from theses, projects and recent learning → `areas/publico/ideias.md` backlog.
- `/post <topic> [x|linkedin|medium] | publicado <slug> <url> | resultado <slug>` — drafts, tracks and closes posts in `areas/publico/posts/`. The agent never publishes.
- `/decisao <frente>` — records a work decision in `areas/trabalho/frentes/<frente>.md` (LGPD: roles, never personal data).
- `/tese nova|revisar|desafiar|listar` — public positions in `areas/teses/`: argument, evidence, what would change the user's mind.
- `/projeto novo|continuar|publicar|listar` — public projects in `areas/projetos/`, the strongest form of public output.
- `python scripts/os_status.py [--human]` — deterministic state (no LLM): public output, due cards, tracks, posts, theses, projects, journal, inbox.
